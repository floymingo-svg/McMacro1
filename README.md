# MC Macro — плавающий автокликер (учебный проект)

Плавающая панель в стиле Game Space + кнопка HIT с удержанием. Клики идут через
AccessibilityService (`dispatchGesture`) или через Shizuku (`injectInputEvent`).

## Сборка APK

1. Открой папку проекта в Android Studio (Ladybug или новее, JDK 17).
2. Дождись Gradle Sync (подтянет Gradle 8.9, AGP 8.7.3, Kotlin 2.0.21, Shizuku API).
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`.
   Или в терминале: `gradle assembleDebug` (если есть wrapper — `./gradlew assembleDebug`).
4. APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Первый запуск на телефоне

1. Установи APK, открой «MC Macro».
2. Кнопка 1 — разрешение «поверх других окон».
3. Кнопка 2 — включи службу Accessibility. На Android 13+ для APK не из магазина пункт
   может быть серым: *Настройки → Приложения → MC Macro → ⋮ → Разрешить ограниченные настройки*.
4. (Опционально) Shizuku: запусти Shizuku, нажми кнопку 3, потом в панели переключи «Метод».
5. «Запустить плавающее окно», открой Minecraft.
6. В панели нажми «🎯 Задать цель», перетащи перекрестие на точку удара (кнопку атаки
   или место, куда бьёшь), нажми «✔ Сохранить цель». Делай это в той же ориентации
   (ландшафт), в которой играешь.
7. Кнопкой «✥ Двигать HIT» помести HIT-кнопку под палец, выключи режим.
8. Зажми HIT — идут клики. Вторым пальцем води камеру.

## Как решён мультитач

Не делай один полноэкранный оверлей, который ловит всё и «пробрасывает» касания:
пробросить живой жест в другое окно нельзя. Вместо этого:

- Оверлей состоит из **нескольких маленьких окон** (панель, HIT, маркер), каждое по размеру
  своего содержимого — остальной экран принадлежит игре.
- У окон флаги `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL | FLAG_SPLIT_TOUCH`:
  касания вне окна уходят в игру, а split touch позволяет разным пальцам одновременно
  работать с разными окнами.
- Поэтому палец №1 на HIT обрабатывает `HitButtonView`, палец №2 на камере попадает
  напрямую в Minecraft. Никакого `ACTION_POINTER_DOWN`-проброса не нужно; в
  `HitButtonView` лишь отслеживается свой `pointerId`, чтобы hold закончился
  именно когда отпущен нужный палец.
- Сами клики — отдельный инъецированный «палец» в точке цели. Эта точка должна лежать
  вне окон оверлея (маркер цели после сохранения удаляется).

## Jitter

Каждый клик привязан к сетке `i * 1000/CPS`, шум (гауссов, ±2σ) добавляется к моменту
клика, а не накапливается. Средний CPS остаётся заданным, интервалы плавают.
Ползунок Jitter 0–100% задаёт σ (до 25% периода).

## Ограничения (проверь на своём устройстве)

- Проект не компилировался автоматически при создании — возможны мелкие правки
  под твою версию Android Studio/AGP.
- Accessibility: каждый жест — IPC + задержка системы, реалистичный потолок обычно
  ~20–30 CPS, зависит от прошивки. Высокие CPS даёт Shizuku.
- Shizuku: скрытый API `IInputManager.injectInputEvent` мог поменяться в новых версиях
  Android; при ошибке исключение глотается в `InputService.inject()` — смотри logcat.
- Одновременная работа инъецированного и реального касаний зависит от версии Android и
  прошивки. Если камера «дёргается» при кликах — попробуй другой метод.
- Многие серверы запрещают автокликеры и могут банить — используй в своих мирах.
